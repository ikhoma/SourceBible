# Observation

In the book picker, searching for a book that doesn't exist (e.g. "Gens") shows
just the two section headers ("Old Testament" / "New Testament") with nothing
underneath — no feedback that the name matched no book. An invalid book looks
"accepted."

## Why it matters

An empty list with only headers reads as a loading glitch, not "no match." The
user gets no signal that their query is wrong or how to recover.

## Possible direction

Add an empty state (icon + text), e.g. "No such book".

## Screenshots

- `../img/19.jpg` — search "Gens" → bare OT/NT headers, no feedback.

## Implementation (2026-07-16)

**Changed:**
- `BookChapterPickerView.swift` — `bookList` now shows a `ContentUnavailableView`
  ("book.closed" icon + "No such book" + a spelling hint) when the trimmed query
  matches no book in either testament (`searchHasNoMatches`). Otherwise the themed
  list renders as before. `.searchable` stays attached to the container so the
  search field remains and the user can correct the query in place.
- `Localizable.xcstrings` — added `picker.no_book_found` and
  `picker.no_book_found.hint` (en + uk).

Scope: list mode only — tile mode has no search bar. `ContentUnavailableView` is
iOS 17+ (min target iOS 18, no availability guard needed).

**Verify on device:** open book picker, type a nonsense name → empty state appears;
clear the query → full OT/NT list returns; check the UA UI shows "Такої книги немає".
