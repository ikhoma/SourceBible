# Observation

On first launch the tester tapped **OK** on the "Help improve Source Bible" card
and reported that "nothing happens" — they expected a next window or the App Store
review prompt to open.

## Why it matters

The card is the one-time **analytics-consent** sheet. OK works exactly as designed:
it grants consent and dismisses the sheet. But the sheet sits over the reader, which
is already visible behind the translucent surface, so the only feedback is the sheet
sliding away — there is no confirmation, no next step. On a first launch that subtle
dismissal reads as "the button is dead." The behaviour is correct; the *feedback* is
what's missing.

## Reclassification (bug-015 → ux-019)

Not a defect. Reclassified per Ivan's call. Investigation:

- The "first launch dialog" is `AnalyticsConsentCard` (`AnalyticsConsentModifier`,
  attached via `.analyticsConsentIfNeeded()` on the root).
- **OK** (`analytics.consent.accept`) → `analyticsEnabled = true`, `isPresented = false`.
- **Not now** (`analytics.consent.decline`) → `analyticsEnabled = false`, `isPresented = false`.
- Either path sets `consentShown = true`, so the card never appears again.
- There is deliberately **no** next window and **no** App Store review here — the tester's
  expectation was mistaken. OK simply records consent and closes the sheet to reveal the
  reader (Genesis 1, already on screen behind it).

## Possible direction (discoverability decision — needs Ivan)

- **A — accept as-is.** Behaviour is correct; leave it. Lowest cost.
- **B — add a light confirmation** on OK (brief toast / inline checkmark) so the tap feels
  acknowledged before the sheet dismisses.
- **C — a small cross-fade / haptic** on dismiss so the state change is perceptible.

No behaviour change has been made. This card only documents the finding and the options.
