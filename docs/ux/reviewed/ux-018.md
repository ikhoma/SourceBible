# Observation

The Original tab section title switches only two ways — OT → "Original Text in
Hebrew Word by Word", NT → "…in Greek…" (`sectionTitleKey` in
`OriginalWordsView`, VerseTabContent.swift, keyed off `testament`). The Aramaic
passages of the OT are therefore labeled "Hebrew", which is technically wrong
for those verses.

Affected passages (canonical, fixed): Dan 2:4b–7:28, Ezra 4:8–6:18, Ezra
7:12–26, Jer 10:11. (Gen 31:47 contains only two Aramaic words — keep it
labeled Hebrew.)

## Why it matters

For an app whose whole point is precision about the original languages, telling
the reader that Daniel 3 is "Hebrew" undermines trust exactly with the audience
(students, pastors) most likely to notice.

## Possible direction

Decision (agreed 2026-07-16): **hardcode the canonical Aramaic ranges** — they
are fixed and well-known, ~20 lines, no DB change.

- Static check `isAramaic(book:chapter:verse:)` over the ranges above; in
  `OriginalWordsView.sectionTitleKey` return a new key
  `verse.section.original.aramaic` when it matches (Dan 2:4 itself is mixed
  Hebrew→Aramaic mid-verse; labeling the whole verse Aramaic is acceptable, or
  start at 2:5 — decide at implementation).
- New Localizable.xcstrings entry: en "Original Text in Aramaic Word by Word",
  uk "Оригінальний текст арамейською слово за словом".

Why not per-token data: the DB currently has no Aramaic marker — `word.language`
is only `hbo`/`grc` (Aramaic tokens imported as `hbo`), Macula's H/A morph
prefix was stripped (leading "A" in `morph` = adjective), and `strongs.language`
is `hbo` for Aramaic entries too. Re-importing Macula with the lang attribute
would give word-level accuracy but touches the build pipeline + DB for the same
~270 verses — not worth it now.
