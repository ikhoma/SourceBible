# Product Decision — Analytics (Mixpanel)

## Status
Proposed (потребує підпису Ivan)

**Date:** 2026-06-19
**Deciders:** Ivan

---

## Context

На етапі бета-тестування потрібні продуктові метрики, щоб зрозуміти:
- чи повертаються користувачі (engagement / retention),
- як вони шукають (search behavior),
- які фічі «беруть», а які — мертвий вантаж (feature adoption),
- **і головне — чи досягаємо місії: люди реально *досліджують* текст, а не просто відкривають додаток (Meaningful Study Session).**

**Напруга з [[PDR-Auth-Strategy]] (trust-first).** Той PDR прямо вимагає: no login wall, local-first, sync opt-in, бо додаток зберігає глибоко особисте (молитви, рефлексії). Збір usage-даних третьою стороною (Mixpanel) суперечить цьому духу, якщо зроблено необережно. Це рішення має узгодити аналітику з trust-first, а не порушити його.

## Decision (proposed)

1. **Аналітика = Mixpanel, у беті І в проді.** Гейтиться на тумблері згоди «Share anonymous usage» (default ON), **не** на build-флазі. Реліз з вимкненою згодою → `NoopAnalytics` (нуль мережі). Абстракція `AnalyticsService` дозволяє замінити Mixpanel на власну реалізацію без переробки call-sites, коли free-tier перестане вистачати (див. D3).
2. **Анонімність.** distinct_id = **PreAuthIdentity** ([[ADR-012-unified-user-data-layer]]) — без логіну, без PII. Retention працює без акаунта → trust-first не страждає.
3. **Лише лічильники й факти подій.** Жодного тексту нотаток, жодних особистих даних. Дискусійний виняток — текст пошукового запиту (див. Open Decisions).
4. **North Star — Meaningful Study Session (MSS):** «тижневі користувачі з ≥1 MSS». MSS міряє місію (глибина дослідження), а не марнославну DAU.
5. **Визначення метрик — у Mixpanel, не в білді.** Додаток шле багаті атомарні події + одну per-session `study_session_summary` (лічильники). MSS, adoption-вікна, воронки визначаються у Mixpanel і тюняться **без нового релізу**. Єдине незмінне постфактум — дані, яких не надіслали; тому taxonomy має бути достатньо повною з першого разу (див. spec).

## Decisions

### D1 — текст пошукового запиту — ✅ ВИРІШЕНО (2026-06-19): НЕ слати
`search_committed` несе лише `results_count`, `translation`, `testament_filter`, `had_zero_results`. **Жодного raw-тексту запиту** (запит = контент користувача). Якщо колись знадобляться топ-запити — окреме рішення з агрегованим/хешованим джерелом.

### D2 — згода на збір у бета — ✅ ВИРІШЕНО (2026-06-19)
**Контекст:** бета без цільової EU/UK бази (поодинокі тестери з Лондона — укр. громадяни).
**Юр-нюанс:** GDPR/UK-GDPR визначається **фізичним місцеперебуванням**, не громадянством → тестер фізично в Лондоні технічно в scope UK-GDPR. Але для крихітної закритої бети з анонімною first-party аналітикою (D1: без тексту запиту; anon PreAuthIdentity; без ATT, бо Mixpanel не юзає IDFA і не «tracking» за Apple) ризик мізерний. TestFlight-тестери й так погоджуються на збір crash+usage при вступі.

**Рішення:** тумблер у Settings **«Share anonymous usage» (default ON)** + одноразова нотатка; **ініціалізація Mixpanel гейтиться на цьому тумблері**. Без блокуючого opt-in промту (немає цільової EU-бази), але користувач може вимкнути. Покриває London edge-case, лягає під trust-first, футур-пруфить прод. *(Не юр. консультація.)*

### D3 — доля аналітики в проді — ✅ ВИРІШЕНО (2026-06-19)

**Рішення:** аналітика **УВІМКНЕНА і в проді** — той самий Mixpanel, що в беті, гейтнутий на тумблері згоди «Share anonymous usage» (default ON, як D2), **не** на `#if BETA`. Privacy-обмеження зберігаються: анонім (PreAuthIdentity), без PII, без raw-тексту запиту (D1). Реліз з вимкненою згодою → `NoopAnalytics`.

**План міграції на кастомну аналітику:** Mixpanel — тимчасове рішення на free-tier (1M подій/міс, поновлюється щомісяця). Коли безкоштовного плану перестане вистачати — замінити `MixpanelAnalytics` на власну реалізацію `AnalyticsService` (свап через наявну абстракцію, без зміни call-sites). Окремий remote kill-switch не потрібен.

Pros/Cons (для контексту; обрано Pro-сторону з privacy-мітигаціями — opt-in, анонім, без тексту запиту):

| | Pro | Con |
|---|---|---|
| Дані | Реальний масштаб; валідація MSS/retention/adoption на справжніх юзерах | Trust-first конфлікт: usage глибоко особистого додатку → третій стороні; репутаційний ризик |
| Рішення | Видно drop-off; пріоритизація фіч по факту | Юр. тягар: GDPR-згода, App Privacy labels, data-subject requests |
| Цикл | Постійний фідбек після релізу | Вартість Mixpanel росте → тригер міграції на кастомну (вище) |

## Trade-offs

| Маємо | Ціна / ризик |
|---|---|
| Бачимо чи досягаємо місії (MSS), retention, adoption, пошук | Треба коректно гейтити, щоб нічого не протекло в прод |
| Анонімно, без логіну → trust-first збережено | Mixpanel збирає ідентифікатори пристрою → потрібен `PrivacyInfo.xcprivacy` |
| Пороги/воронки тюняться в Mixpanel без релізу | Не виправити постфактум те, чого не надіслали → taxonomy має бути повна одразу |

## App Store / Privacy

- **`PrivacyInfo.xcprivacy`** обовʼязковий — Mixpanel збирає ідентифікатори; без декларації App Store відхилить навіть бета-сабміт.
- Mixpanel-token **не комітити** в код — через `.xcconfig`/build setting.
- Гейтинг на тумблері згоди (бета + прод): згода OFF → `NoopAnalytics`, нуль мережі. App Privacy labels + GDPR-згода обовʼязкові для публічного релізу (D3).

## Consequences

- Зʼявляється новий шар `AnalyticsService` (див. `spec-analytics-mixpanel`).
- Нові події інструментуються в Reader, Search, Notes/анотаціях, перемиканні перекладів.
- Залежність: Mixpanel Swift SDK (SPM) — перед інтеграцією перевірити Swift 6 strict concurrency сумісність.
