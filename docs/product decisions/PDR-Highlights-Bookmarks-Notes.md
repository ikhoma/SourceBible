\# Product Decision Record  
\# Notes, Highlights and Bookmarks Differentiation

\#\# Status

Accepted

\---

\# Problem

Bible study applications often blur the distinction between:

\- Highlights  
\- Bookmarks  
\- Notes

When multiple features can be used to achieve similar goals, users become confused and build inconsistent mental models.

The goal is to create a system where each feature has a clear purpose and aligns with how Christians commonly interact with physical Bibles.

\---

\# Product Principle

\> Match the real-world behavior of Bible readers.

Users should immediately understand why a feature exists without reading documentation.

\---

\# Mental Model

Each feature answers a different question.

| Feature | User Question |  
|----------|----------|  
| Highlight | What is important here? |  
| Bookmark | Where do I want to return? |  
| Note | What do I think about this? |

\---

\# Highlights

\#\# Purpose

Highlights are used to mark meaningful text.

This mirrors how people use colored markers in physical Bibles.

Examples:

\- God's character  
\- Promises  
\- Commands  
\- Sin  
\- Prayer  
\- Prophecy

\---

\#\# User Intent

\> This text belongs to a theme or category.

Not:

\> I want to return here later.

\---

\#\# Features

\#\#\# MVP

\- Color  
\- Category (optional)  
\- Search  
\- Filter by category

\---

\#\# Example Categories

\- God  
\- Promises  
\- Commands  
\- Prayer  
\- Faith  
\- Sin

Users may create their own categories.

\---

\#\# Why Categories Belong Here

Categories classify the meaning of the text itself.

This matches common Bible study practices.

\---

\# Bookmarks

\#\# Purpose

Bookmarks are navigation tools.

They help users quickly return to a location.

\---

\#\# User Intent

\> I want to come back here later.

Not:

\> I want to classify this text.

\---

\#\# Features

\#\#\# MVP

\- Create bookmark  
\- Remove bookmark  
\- Quick navigation

\---

\#\# No Categories

Categories intentionally do not belong to bookmarks.

Reason:

Categories create overlap with highlights and future study notes.

\---

\#\# Examples

\- Continue reading tomorrow  
\- Return to this chapter later  
\- Keep a place for current study

\---

\# Notes

\#\# Purpose

Notes store the user's thoughts.

\---

\#\# User Intent

\> I want to save my own understanding.

\---

\#\# MVP Features

\- Plain text note  
\- Optional verse attachment

\---

\#\# Future Evolution

Notes will become Study Notes.

Study Notes may contain:

\- Multiple verses  
\- User text  
\- Quotes  
\- AI generated content  
\- Commentary references  
\- Word studies

\---

\# Why Not Use Bookmark Categories

A bookmark category such as:

\- Home Group  
\- Sermon  
\- Personal Study

is not actually classifying text.

It is classifying a workflow.

This creates overlap with future Study Notes.

\---

\# Future Information Architecture

\#\# Reading Layer

\- Highlights

Purpose:  
Mark meaningful text.

\---

\#\# Navigation Layer

\- Bookmarks

Purpose:  
Return to locations.

\---

\#\# Knowledge Layer

\- Notes  
\- Study Notes

Purpose:  
Store understanding, observations and research.

\---

\# Long-Term Vision

Highlights classify text.

Bookmarks navigate content.

Notes build knowledge.

Each feature has a unique purpose and does not compete with the others.
