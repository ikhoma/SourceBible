# ADR-036: Український шар глос — наскрізні одиниці перекладу

**Status:** Proposed
**Date:** 2026-08-24
**Deciders:** Іван
**Пов'язані:** ADR-006 (локалізація, TranslationProvider), ADR-027 (модульні модулі, OTA), ADR-029 (Огієнко UBIO'88, CC BY-SA 3.0), ADR-019 (джерело Strong's-леми), `docs/original-tab.md` (модель слот/токен)

---

## Context

Вкладка «Оригінал» показує україномовному користувачеві **англійські** глоси (`gloss_display`, похідна від Macula). Для української аудиторії це головна діра в локалізації: інтерфейс український, а змістовий шар — ні.

### Чому не «перекласти кожне слово»

Наївний підхід — перекласти кожне входження. Заміряно на Macula Hebrew (`macula-hebrew.tsv`, WLC):

| | значення |
|---|---|
| слотів (те, що бачить око як «слово») | **305 349** |
| з них багатотокенних | **46.4%** (141 669) |
| унікальних одиниць за (Strong:morph)+контекстна глоса | **78 451** |

Тобто перекладати треба **вчетверо менше**, ніж є слів на екрані. Це і є підстава для наскрізного шару одиниць замість шару входжень.

### Чому контекстна глоса входить у ключ

Якщо ключем зробити лише (Strong, morph), одиниць стає 49 371. Різниця в **29 080 одиниць** існує виключно тому, що Macula дає різну **контекстну** глосу тим самим граматичним формам.

Приклад — אֲשֶׁר (H834, `Tr`), **48 різних контекстних глос** на одну пару (Strong, morph):

| глоса | входжень |
|---|---|
| which | 2 566 |
| who | 681 |
| that | 581 |
| whom | 298 |
| **where** | **207** |

Якби ключем був Strong, усі 3 454 місця дістали б «який» — включно з 207, де правильно «де».

Аналогічно עַל (H5921, `R`) — 38 глос, בְּנֵי (H1121, `Ncmpc`) — 38 глос.

**13 350 груп (27%) мають більше однієї контекстної глоси, і вони покривають 80.3% усіх слотів на екрані.**

### Що ключ свідомо ігнорує

**Огласовку.** 86.1% повторюваних одиниць трапляються більш ніж з однією огласованою формою (паузальні форми, макаф, дагеш). Це навмисно: `כָּתַב` і `כָּתָ֑ב` — одна одиниця, українська глоса однакова. Огласовка змінює вимову, не переклад.

### Відмінок — діра, знайдена при перевірці таблиці

Англійська глоса відмінка не несе. `the earth` (`19bef4c79f4a22a9`, 242 входження) в англійській однакове і як підмет, і як додаток. Українською — «земля» проти «зéмлю».

Це вдарило б по **всіх іменниках**, тому питання «чи можна вивести відмінок машинно» стало блокуючим.

#### Грецька — вирішено безкоштовно

У Macula Greek (`macula-greek-Nestle1904.tsv`, 137 779 рядків) колонка `case` заповнена на **57.7%**:

| case | токенів |
|---|---|
| nominative | 24 197 |
| accusative | 23 031 |
| genitive | 19 515 |
| dative | 12 126 |
| vocative | 649 |

Незаповнене — сполучники, прийменники, прислівники, особові форми дієслова, тобто те, що відмінка не має за визначенням.

**Відмінок уже сидить у `morph`** (`N-NSM` проти `N-ASF`), а `morph` уже входить у підпис одиниці. Грецькі іменники **вже розділені за відмінком** без жодних змін. Робити нічого не треба.

#### Іврит — виводиться частково

Біблійний іврит відмінкових закінчень не має. Але Macula несе три сигнали:

| сигнал | покриття | що дає |
|---|---|---|
| `frame` (PropBank A0/A1) | **94.7% дієслів** (69 205 з 73 055) | A1 = пацієнс → знахідний |
| `state` | 76.7% іменників (construct 39.1%, absolute 37.0%) | construct → наступний у родовому |
| прийменник у слоті | — | уже в підписі одиниці |

`frame` вказує на конкретні ID слів: для ברא (Бут. 1:1) — `A0:…0031; A1:…0052;…0072`. Це **анотація людьми**, не евристика. 29 344 ID позначено як A1; з `xml:id` зматчилось 29 101 (**99.2%**).

#### Скільки лишається невиведеним — заміряно

Слотів, що містять іменник: **144 983** (47.5% усіх).

| | слотів | % |
|---|---|---|
| однозначний тег із Macula | 71 575 | **49.4%** |
| конфлікт тегів | 7 457 | 5.1% |
| **тега немає взагалі** | **65 951** | **45.5%** |

**50.6% івритських іменникових слотів не отримують відмінка з Macula ні в якому вигляді.** `frame` покриває дієслівні аргументи, `state` — конструктні ланцюги; підмети, іменні присудки й обставини лишаються німими.

Це не дефект реалізації — це межа джерела.

#### Українські переклади як оракул відмінка

У `data/` є два українські переклади. Перевірено програмно:

| | UBIO'88 (Огієнко) | GRM (Громов) |
|---|---|---|
| `info.language` | uk | uk |
| віршів | 31 170 | 31 167 |
| і / ї / є / ґ | 2813 / 400 / 164 / 39 | 2721 / 401 / 199 / 26 |
| ы / э / ъ | 0 / 0 / 0 | 0 / 0 / 0 |

Обидва — справжня українська, російських літер нема. Версифікація розходиться на 3 вірші з 31 тисячі, тож зіставляються практично 1:1 без карти відповідностей.

У тексті присутня inline-розмітка (латинські літери `b f i p` / `d f i n s` = імена тегів, 0.6–0.9% символів) — знімається за правилом ADR-034 перед морфоаналізом.

**Правові підстави:** Огієнко — ліцензія підтверджена в ADR-029 (CC BY-SA 3.0). Щодо Громова власник продукту дав письмову позицію, що видобування граматичної ознаки не створює похідного твору. Рішення власника, зафіксоване тут як вхідна умова, не як юридичний висновок цього документа.

### Ціна відмінка в ключі — заміряно

| | одиниць |
|---|---|
| без відмінка | 78 451 |
| **з відмінком** | **94 743** (+20.8%) |

Економіка повторюваності майже не постраждала:

| | одиниць-повторів | покривають слотів |
|---|---|---|
| без відмінка | 26 366 | 253 264 (**82.9%**) |
| з відмінком | 28 542 | 239 148 (**78.3%**) |

Втрата — 4.6 процентних пункти, бо **розпалась лише 14.3% одиниць** (11 251). Решта 85.7% завжди трапляються в одній синтаксичній ролі.

### Розмір модуля — заміряно

Синтетична база на 94 743 рядки, глоси реалістичної довжини (11.3 символа = 22.6 байта в UTF-8), з індексом:

| ключ | файл | gzip |
|---|---|---|
| **BLOB(16)** | **4.34 МБ** | 3.05 МБ |
| TEXT (hex, 32) | 5.81 МБ | 3.42 МБ |

Ліміт бандлу застосунку — **4 ГБ** (iOS 18+). Модуль займає **0.15%**. Питання доставки знімається розміром.

Окремо: **On-Demand Resources оголошено застарілими з iOS 27**, Apple скеровує на Background Assets. Будувати докачування на ODR було б помилкою вже сьогодні.

### Стан якості вхідних даних

Пілот гілки A дав **65% точності**. Тому шар публікується зі статусом, а не як готовий переклад (див. Рішення 4).

## Decision

### 1. Одиниця перекладу і ключ

```
unit_sig = "<Strong>:<morph>[+<Strong>:<morph>…]|<контекстна глоса>|<відмінок>"
unit_key = sha256(unit_sig)[:16]   -- BLOB(16), не hex-TEXT
```

Відмінок виводиться **у білд-конвеєрі** з `case` (грецька) або `frame` + `state` + оракула українських перекладів (іврит). Ніколи не обчислюється у Swift.

### 2. `unit_key` — колонка в `word`

`word` дістає 21-шу колонку `unit_key BLOB`. Не окрема таблиця, не обчислення в рантаймі.

Підстава: окрема таблиця додає join на гарячому синхронному шляху `loadWords` — постійна ціна замість разової перезбірки. Обчислення у Swift створює **третю** копію правила «які токени зліплюються в слот» (уже є в `build_pilot_sample.py` і `displayWords`); докстрінг пілотного скрипта фіксує, що ці двоє **вже одного разу розійшлись** і це коштувало повної переробки.

### 3. Два рівні: одиниця + override

- `gloss_unit(unit_key, gloss_uk, status, n_slots)` — дефолт на одиницю;
- `gloss_override(book, chapter, verse, slot, gloss_uk)` — на конкретне входження, відвантажується **порожнім**.

Override існує для того, що ключ не вловлює за побудовою — насамперед **референт**: `H1931` («він») у Бут. 1 і в Пс. 23 має однакові Strong, morph і глосу, отже один ключ, але «він» проти «Він» вирішує те, про кого мова.

### 4. Read-path

```sql
COALESCE(ovr.gloss_uk, gu.gloss_uk, <англійський ланцюг>)
```

`lang` — bind-параметр, не конкатенація. Модуль ATTACH-иться **завжди**: або реальний, або порожній stub, щоб уникнути двох гілок SQL.

### 5. Статус і показ

Сирий машинний переклад **показуємо**. Один **beta-бейдж на весь український шар**, поки не вичитано все; зникає на 100%.

Не на книгу, не на слово. Бейдж — обіцянка «тут ще не пройшла людина», і його не можна лишати після вичитки.

`status` на одиницю (raw-mt / reviewed) лишається **як стан робочого процесу вичитки**, не як дані для рендера.

### 6. Доставка — все в бандлі

Жодного сервера, ODR чи логіки докачування у v1.

Два запобіжники, що коштують нуль:

1. модуль — **окремий ATTACH-абельний файл**, не вкомпільований у ядро;
2. чотири поля версій усередині модуля:

```
module_version      alignment_version
unit_key_version    case_rule_version
```

Без них при появі доставки неможливо визначити, що встановлено в користувача — єдиним виходом стане примусове перекачування всім.

### 7. Вирівнювання — вхід у білд, не крок білду

Зіставлення «слот джерела ↔ слово українського перекладу» виконується **один раз офлайн**, результат заморожується як TSV у репо, білд читає TSV детерміновано.

Це умова відсутності дрифту: недетермінованість карантинується в одноразовому артефакті, який лежить у git і читається очима. Патерн уже вживаний у проєкті (`branch_a.tsv` / `branch_b.tsv`).

### 8. Майстер-формат

TSV на мову, сортований за `unit_sig` (стабільний diff), окремий TSV на override.

## Options Considered

### Ключ одиниці

| Варіант | Одиниць | Чому ні |
|---|---|---|
| Strong | ~8.7 тис. | H834 → «який» у 207 місцях, де треба «де» |
| Strong + morph | 49 371 | те саме, слабше: 27% груп мають >1 глоси, покривають 80.3% слотів |
| **+ контекстна глоса + відмінок** | **94 743** | **обрано** |
| на входження | 305 349 | вчетверо дорожче, без виграшу в якості |

### Розміщення `unit_key`

| Варіант | Ціна |
|---|---|
| **колонка в `word`** | **разова: +1 колонка, одна перезбірка (~10 хв)** |
| таблиця `word_unit` | постійна: join на `loadWords` |
| обчислення у Swift | третя копія правила слотів; прецедент розходження вже був |

### Доставка

| Варіант | Чому ні |
|---|---|
| **бандл** | **обрано: 4.34 МБ = 0.15% ліміту** |
| ODR | застаріле з iOS 27 |
| власний сервер | розв'язує задачу каталогу, якої в нас нема (YouVersion качає, бо в них тисячі перекладів на вибір; у нас один модуль на мову інтерфейсу) |

### Бейдж

| Варіант | Чому ні |
|---|---|
| **один на шар** | **обрано** |
| на книгу | вимагає покнижного статусу в модулі без виграшу для користувача |
| на слово | шум; бейдж на кожному другому слові перестає щось означати |

## Consequences

### Приймаємо

- **Зміна схеми ядра** — `word` +1 колонка. Поточний scope роботи це виконувати **забороняє** (`DENY: зміни схеми`); ADR фіксує рішення, реалізація потребує окремого дозволу.
- **Повна перезбірка бази** — разово, ~10 хв. База перезбирається від будь-якої зміни конвеєра.
- **Новий версіонований артефакт** — заморожене вирівнювання зі своїм життєвим циклом.
- **Нова маленька таблиця** — керування українських дієслів: відмінок джерела ≠ український відмінок («боятися Бога» — родовий, «керувати народом» — орудний). Ключ — пара (дієслово, роль), не входження, тож таблиця скінченна й не роздуває override.
- **Виправлення глос їдуть релізами App Store**, батчами. Стає болем лише коли захочеться правити частіше, ніж виходять релізи — **продуктовий поріг, не архітектурний**.

### Знято порівняно з першою редакцією

- ~~`unit_book` і покнижне оновлення модуля~~ — при бандлі не має сенсу;
- ~~ідемпотентний upsert по книгах~~;
- ~~тертя з ADR-027 (наскрізний шар проти покнижної одиниці оновлення)~~;
- ~~блокуючий гейт на продуктивність JOIN~~ → знижено до `EXPLAIN QUERY PLAN`, підстава нижче.

### Гейти реалізації

1. **`EXPLAIN QUERY PLAN` на копії бази із синтетичним модулем має показати `SEARCH … USING INDEX`.** Скан — єдиний сценарій, у якому тут можна отримати мілісекунди.
2. **Orphan-check у білді:** жоден `word.unit_key` не лишається без рядка в майстер-TSV → `exit(1)`.
3. **Матч ID для `frame`:** ≥99% A1-ідентифікаторів мають зматчитись із `xml:id` (заміряно 99.2%; падіння нижче = зміна формату Macula).
4. Замір часу на **фізичному** пристрої (не симуляторі), p95, A/B у одному прогоні, з прогрітим кешем — **звичайна перевірка перед мерджем**, не умова входу.

### Чому гейт продуктивності знижено

Десктоп-рісьорч (документація SQLite, форум, зокрема гілка саме про розбиття бази на кілька файлів) **не дав жодного опублікованого заміру** штрафу на крос-базовий JOIN. Але механізм задокументовано:

- `PRAGMA cache_size` документований як ліміт **«per open database file»** із префіксом схеми → приєднаний модуль має **власний кеш** і не витісняє закешовані сторінки `word`. Це знімало головну тривогу;
- `SQLITE_MAX_ATTACHED` = 10 за замовчуванням, максимум 125; нам треба 1–2;
- пошук у B-дереві на 94 тис. рядків — близько 17 порівнянь; `loadWords` віддає 10–30 токенів на вірш.

Реальна вартість ATTACH — **разова, на старті застосунку** (відкриття другого файлу, кешування схеми), не на кожному вірші.

## Відкрите — не заміряно

Чесний перелік того, чого цей ADR **не** знає:

1. **Покриття вирівнювання** з українськими джерелами. Переклади парафразують; не кожен слот матиме відповідник. Непокриті падають назад на `frame`/`state`. Число невідоме.
2. **Розмір таблиці керування українських дієслів.**
3. **Кількість одиниць для грецької.** Усі виміри в цьому документі — **іврит**. НЗ окремо не рахувався.
4. **Пристрій для заміру** — потрібен найповільніший із флоту тестерів (мінімум iOS 18).
