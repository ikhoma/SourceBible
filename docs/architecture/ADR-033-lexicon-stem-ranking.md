# ADR-033 — Лексикон: порода цієї форми, а не діапазон кореня

**Status:** Accepted (2026-08-03)
**Context tags:** lexicon, BDB, morphology, word study, Hebrew binyanim
**Related:** ADR-016 (Strong's gating), `spec-word-usage-redesign.md`, `unified_word_lookup_system_design.md`, `WordTabContent.swift`

---

## Контекст

Вкладка «Слово → Значення» показує розібрану словникову статтю BDB. Для
івритського дієслова стаття має двошарову структуру:

```
1)   to cease, cause to cease, cut off, destroy, perish   ← заголовок кореня
1a)  (Qal)
1a1)   to cease
1a2)   to cause to cease, destroy
1b)  (Niphal)
1b1)   to be cut off
```

`LexiconParser` це вже розбирає: рядок `1)` стає секцією без імені
(`stemName == ""`), `1a)` / `1b)` — секціями з іменами порід. Рендеряться вони
**в порядку джерела**, тож першим і найпомітнішим іде заголовок кореня.

**Проблема — не в наявності інших порід, а в порядку й позначенні.**

Ос. 4:6, `נִדְמוּ` — Niphal perfect 3cp, «мій народ **знищено**». Екран показує
першим рядком «to cease, cause to cease, **destroy**, perish». Читач бачить
активне «destroy» на найпомітнішому місці й доходить висновку, що народ *нищить*.
Niphal — пасив; секція з правильним «to be cut off» лежить нижче, врівні з
рештою порід.

Це класична помилка, яку Джеймс Барр назвав **illegitimate totality transfer**:
приписати конкретній формі весь семантичний діапазон кореня. Наш поточний порядок
не просто її допускає — він до неї підштовхує, бо ставить злиту глосу першою.

## Рішення

### 1. Злитий заголовок кореня прибираємо — якщо є породи

Секція з `stemName == ""`, що стоїть ПЕРЕД першою іменованою секцією, не
рендериться, коли в статті є хоча б одна порода. Вона не є значенням жодної
конкретної форми — це склейка діапазону, артефакт друкованої статті, де вона
слугувала заголовком.

⛔ **Коли порід немає** (іменники, частки, короткі глоси, грецький аутлайн
Abbott-Smith) ця секція — єдиний вміст. Там нічого не змінюється.

### 2. Породу розібраної форми піднімаємо нагору й позначаємо

Секція, що збігається з породою з `word.morphology`, стає першою й отримує
позначку «ця форма». Решта — нижче, у порядку джерела, під тихішим заголовком.

Порядок стає: **що означає ЦЕ слово тут** → потім **як воно поводиться в інших
породах**.

### 3. Ключ звірки — код породи, не підпис

BDB підписує секції англійською (`Niphal`), а `MorphologyDecoder` віддає
**локалізовану** назву (`stemNiphal` → «Ніфаль»). Звіряти підписи не можна —
українською не збіжиться ніколи.

Звірка йде через канонічний код OSHB (`q N p P h H t D`) → канонічна англійська
назва → нормалізований (lowercase, без пробілів) збіг з `stemName`.

## Чому не так

- **Прибрати інші породи взагалі.** Найгірший варіант. Івритське дієслово не має
  значення окремо від породи: Qal «припинитися» → Niphal «бути знищеним» →
  Piel «нищити». Побачити Niphal ПОРУЧ із Qal — це і є спосіб зрозуміти форму.
  Прибрати решту = прибрати дериваційну логіку, заради якої відкривають оригінал.
- **Згорнути інші породи в «показати ще».** Ховає ту саму логіку за зайвим тапом.
  Ранжування вже вирішує проблему помітності; згортання додає взаємодію без
  виграшу. Якщо стаття виявиться задовгою — повернутись до цього окремо.
- **Лишити злиту глосу, але тихішою.** Півзаходу: вона однаково лишиться першою
  за порядком джерела, а її текст однаково не є значенням цієї форми.
- **Правити дані в базі.** Стаття BDB — джерело, яке ми не переписуємо (ті самі
  міркування, що й у ADR-016 щодо мапінгів). Ранжування — рівень подання.

## Наслідки

**+** Перше, що бачить читач, — значення тієї форми, яка перед ним.
Найпоширеніша герменевтична помилка перестає бути шляхом найменшого спротиву.

**−** Порядок статті більше не збігається з друкованим BDB. Для користувача, що
звіряється з паперовим словником, секції стоятимуть в іншій послідовності. Це
свідомий розмін: ми не репринт словника, ми інструмент для конкретного вірша.

**−** Зʼявляється залежність подання лексикону від морфології. Досі
`lexicalSection` залежала лише від `entry.fullDefinition`.

## Обсяг реалізації

- `LexiconParser` — без змін (структура вже є).
- `WordTabContent.lexicalSection` — фільтр злитої секції + ранжування.
- Мапа код → канонічна англійська назва породи (поруч із `hebrewStem`, але
  ОКРЕМА: та локалізує, ця дає ключ звірки).
- Два рядки локалізації: позначка «ця форма» і заголовок «інші породи».

## ⛔ Крайові випадки — кожен має бути покритий

| випадок | поведінка |
|---|---|
| Немає порід (іменник, частка, коротка глоса) | Нічого не змінюється: секція без імені лишається. |
| Грецький аутлайн Abbott-Smith | Одна секція без імені + `outline`. Правило не спрацьовує. |
| Немає `morphology` (слово без розбору) | Злиту глосу **не прибираємо**: підняти нічого, і без неї не лишиться загального значення. |
| Порода розібрана, але секції з нею в BDB **немає** | Те саме: не прибираємо, не ранжуємо. Fail-safe = поточна поведінка. |
| BDB називає рідкісну породу (Polel, Pilpel, Hithpolel), якої немає в 8 кодах OSHB | Збігу не буде → fail-safe. Не вигадувати евристику «схожа назва». |
| Перехід по чевронах міняє слово, `entry` лишається змонтованим | Ранжування має перерахуватись — воно функція від `(entry, word)`, не збережений стан. |

## Верифікація

- **Ос. 4:6 `נִדְמוּ`** (Niphal) — «to be cut off» першим, злитого рядка немає.
- **Слово в Qal того ж кореня** — нагорі Qal, Niphal нижче.
- **Іменник** (напр. H7225 `רֵאשִׁית`) — вигляд без змін.
- **Грецьке слово** з аутлайном Abbott-Smith — вигляд без змін.
- **Слово UBIO/Огієнка** (без мапінгу Стронга) — шлях недосяжний, регресії нема.
- Чеврони по словах у межах вірша: породи перемикаються разом зі словом.
