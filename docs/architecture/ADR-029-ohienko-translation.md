## Context

Потрібен український переклад. `UBIO'88.zip` уже в `data/`, але не в `build_db.py`
`TRANSLATIONS`. Інспекція модуля (2026-07-15) дала факти, що визначають рішення:

| факт | значення | наслідок |
|---|---|---|
| `strong_numbers = false`, 0 віршів зі `<S>` | Strong's **немає** | O2-верифікація (Strong's overlap) **не працює** — ні empirical, ні scheme-scoring |
| `russian_numbering = true` | декларує синодальну нумерацію | кандидат схеми №1 = `rso`, як у RST |
| 66 книг, 27 НЗ | повна Біблія | НЗ теж є (читання/паралель; версифікація НЗ — окремо) |
| таблиця `books` з `long_name`/`short_name` укр. («Буття», «Вихід») | рідні назви | напряму живить `book_name` (ADR-018) |
| `UBIO'88.commentaries.SQLite3` у тому ж zip | є коментарі | окрема частина → шлях ADR-027 |

**Версифікація — виміряно (930 ВЗ-глав проти .vrs-схем):**

| збіг зі схемою | глав |
|---|---|
| `rso` (синодальна) | 856 |
| `org` (єврейська = Macula) | 71 |
| жодна (потребує override) | **3**: PSA 114, PSA 141, JER 5 |
| суто `eng` | 0 |

Несподіванка: попри `russian_numbering=true`, розбіжні з rso глави майже всі
збігаються з **org (Macula)** — Огієнко лягає на нашу базу **чистіше, ніж англійські
переклади**. Синодальні лише псалми (велика частина); Тора/історичні книги —
здебільшого єврейський рахунок (identity до ORG).

## Decision

**Переклад Огієнка бандлиться в ядро `sourcebible.db` як першокласний переклад
(нарівні з KJV/ASV/NASB/RST). Його коментарі йдуть окремим модульним шляхом ADR-027.
Версифікація будується конвеєром ADR-028; за відсутності Strong's верифікація —
не O2, а перенесення вже доведеного мапінгу RST.**

### Чому в ядро, а не окремий OTA-модуль

Переклад тісно зв'язаний з ядром: таблиця `verse`, `verse_org` (версифікація),
паралельні переклади, крос-референси, FTS-пошук, `book_name` (ADR-018). Окремий
модуль дублював би всю цю машинерію заради одного перекладу. Модульність ADR-027
виправдана для **коментарів** (слабко зв'язані: вірш→текст) — переклад інша природа.
Плюс: українська — стратегічно центральний переклад для аудиторії застосунку
(український продукт, українські користувачі), йому місце в ядрі як першокласному.

### Верифікація без Strong's — перенесення мапінгу RST

O2 (Strong's overlap) для Огієнка неможливий. Текстове вирівнювання по консонантах
(як BSB) теж — це переклад, не іврит. Тому:

- Мапінг будується тим самим `build_versification.py`: кандидати `[rso, org, eng]`,
  вибір схеми per-chapter за O3 (verse-count).
- **Верифікація = агреcandидат з RST.** Огієнко ≈ RST за версифікацією (обидва
  синодальні), а мапінг RST **повністю доведено O2** (ADR-028). Тому: де глава
  Огієнка структурно збігається з RST-главою — мапінг МУСИТЬ бути ідентичним
  доведеному RST. Розбіжність = червоний прапорець на ручний огляд. Це заміна O2,
  що спирається на доведену роботу, а не на здогад.
- Глави, що збігаються з `org` (71) — identity до Macula, тривіально правильні.
- 3 NONE-глави — явні `overrides.tsv` (PSA 114→116 вже маємо для RST, переносимо;
  PSA 141 і JER 5 — ручний розбір проти єврейського тексту).

**Гейт лишається:** де мапінг Огієнка суперечить перевіреному RST і не має
override — білд це показує, вірш іде в «немає даних», а не в тихий здогад. Той
самий принцип ADR-028: показуємо перевірене або порожньо, ніколи не здогад.

## Options Considered

### Option A: бандл у ядро (прийнято ✅)

| Dimension | Assessment |
|---|---|
| Складність | Low — той самий конвеєр, що для 4 наявних перекладів |
| Інтеграція з ядром | Native — verse_org / parallel / xref / FTS / book_name працюють одразу |
| Верифікація версифікації | RST-proxy (без O2), 3 ручні override |
| Оновлюваність | лише через реліз (переклад стабільний, корекції не потрібні) |

**Pros:** мінімум нового коду; першокласна інтеграція; рідні назви книг у ADR-018.
**Cons:** перезбірка БД для оновлення тексту (не проблема для стабільного перекладу).

### Option B: окремий OTA-модуль (як ADR-027)

**Pros:** оновлення без App Store; ізоляція.
**Cons:** дублювання всієї core-плюмбінг (verse_org, book_name, FTS, parallel, xref)
заради одного перекладу; ADR-027 задумувався під коментарі, не під переклади;
українська — центральний переклад, не периферія. Відкинуто.

### Розщеплення zip

`UBIO'88.SQLite3` (текст) → **ядро** (Option A). `UBIO'88.commentaries.SQLite3`
→ **модульний коментар ADR-027**. Тобто «окремо» стосується тільки коментарів,
і це вже узгоджено ADR-027.

## Consequences

**Легше:**
- Українське читання + паралель + крос-референси + пошук — одразу.
- Вкладка «Оригінал» для Огієнка працює: іврит тягнеться з боку Macula через
  `verse_org`, **незалежно** від тегів перекладу.
- Рідні укр. назви книг наповнюють `book_name` (ADR-018).

**Важче / обмеження:**
- **Немає Strong's** → якщо існує фіча «long-press на слові перекладу → Strong's»,
  для Огієнка вона без даних. Читання й перегляд оригіналу — повноцінні.
- Версифікацію не можна O2-верифікувати → покладаємось на RST-proxy + 3 override.

**Треба переглянути:**
- **Ліцензія (блокер).** UBIO'88 — видання Українського біблійного товариства.
  Огієнко †1972. Перевірити умови розповсюдження ПЕРЕД бандлом (як робили з
  NASB/Owen). Без підтвердженої ліцензії — не шипити.
- **Версифікація НЗ — покрито ADR-028** (розширено на весь канон: НЗ → Macula
  Greek). Огієнко без Strong's, тож НЗ-краї (6 глав: ACT 19, ROM 14/16, 2CO 11/13,
  REV 12) верифікуються так само RST-proxy, не O2.
