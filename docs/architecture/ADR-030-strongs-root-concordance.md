# ADR-030: Кореневий конкорданс через Strong's-деривацію

**Статус:** Accepted (2026-07-20)
**Пов'язано:** розширює ADR-019 (джерело `strongs`), живить ADR-013 (word usage / конкорданс) і ADR-016 (word tap). Не чіпає verse_org (ADR-028).

## Контекст
Тематичні добірки (Search) і картка слова мають показувати рису «через усе Писання» — усі спільнокореневі форми, не лише точну лему. Перевірено (2026-07-20, через базу й сирі джерела): **групування за коренем не кодує жодне джерело** — ні `strongs`/`word`, ні TBESH, ні BSB, ні Macula. Є Strong's-номер, морфологія, `stem` (порода), частина мови — але не триконсонантний корінь.

Macula має семантичні домени (`coredomain`/SDBH), та вони групують **за значенням, не коренем**: зливають різні корені (милосердя r-ch-m + благодать ch-n-n → CORE:036), розщеплюють один корінь за сенсами (rechem «утроба» H7358 → домен тіла) і розсипаються на багатозначних дієсловах (nasa H5375 «нести/прощати» — 20+ доменів). Тому домен — окрема майбутня фіча тематичного браузингу, не заміна кореня.

Наявний конкорданс по точному `strongs_id` (ADR-013) вже покриває форми з тим самим номером (hesed H2617; колокація erekh appayim H750+H639; nasa+avon). Прогалина — форми з **різними** номерами того самого кореня: rakhum H7349 ↔ racham H7355 ↔ rachamim H7356; khanun H2587 ↔ chanan H2603 ↔ chen H2580; emet H571 ↔ emunah H530 ↔ aman H539.

## Рішення
Імпортувати **Strong's-деривацію** з OpenScriptures (Hebrew + Greek), обчислити для кожного номера `root_id` (первинний корінь), зберегти в `strongs`, і додати картці слова рівень «цей корінь» поряд із «це слово».

Джерело: OpenScriptures `StrongsHebrewDictionary` / `StrongsGreekDictionary` — public domain; містить поле `derivation` («from H####», «a primitive root»), якого немає в TBESH (STEPBible). Ліцензійно чисте, паралель ADR-019.

## Схема
```sql
ALTER TABLE strongs ADD COLUMN root_id TEXT;
CREATE INDEX IF NOT EXISTS idx_strongs_root ON strongs(root_id);
```
- `root_id` = Strong's-id первинного кореня (для самого кореня — self).
- Конкорданс кореня: `word JOIN strongs ON word.strongs_id = strongs.id` → `GROUP BY strongs.root_id`.

## Алгоритм (Python 3.9)
1. Розпарсити `derivation` кожного запису → множина батьків (regex `[HG]\d{1,5}[a-z]?`).
2. Граф «номер → батьки»; DFS до вузла з `derivation ≈ "a primitive root"` або без батьків = корінь. Кеш + guard від циклів.
3. Багато батьків → вести гілку до primitive-root; неоднозначність — найкоротший шлях, лишок логувати.
4. Extended Strong's (H1471a): для пошуку кореня нормалізувати до базового номера, `root_id` присвоювати наявному id (узгодити з suffix-логікою ADR-019).
5. Ключі: `strongs.id` = `H####`; Macula `word.strongnumberx` = голі цифри (+ інколи літера) — нормалізувати на джойні.

## UX картки (два рівні)
- **«Це слово»** — точний `strongs_id` (наявний конкорданс, дефолт).
- **«Цей корінь»** — усі `strongs_id` з тим самим `root_id`.
Прямо відображає поділ Рівень-1 / Рівень-2 зі звірки «Божого характеру».

## Ризики / межі
- **Багатозначні корені:** конкорданс кореня для nasa H5375 = 655 місць різних сенсів → шумно. «Слово» лишається дефолтом, «корінь» — опційно; сенс-рівень (Macula `coredomain`/`sensenumber`) — окремий майбутній крок.
- Шум деривації / посилання на не-корені → логувати нерозв'язані.
- Грека — симетрично, через OpenScriptures Greek (не TBESG).

## Acceptance (на темі «Божий характер»; звірити при імпорті)
- r-ch-m: H7349, H7356, H7358 → `root_id` = **H7355**.
- ch-n-n: H2587, H2580 → **H2603**.
- aman: H571, H530 → **H539**.
- hesed: H2617 → **H2616** (chasad).
- nasa H5375, naqah H5352 → self.
- erekh H750 / aph H639 — різні корені, не зливаються.
- Регресія: точний конкорданс (ADR-013) не змінюється.

## Наслідки
Розширює ADR-019; вмикає Рівень-2 картки слова й майбутній кореневий фільтр тематичних добірок. Крок у `build_db.py` після enrich-strongs (окремий `scripts/build_strongs_roots.py`, канонічно через `rebuild.sh`). Робочий скрипт — окремим кроком після прийняття ADR.
