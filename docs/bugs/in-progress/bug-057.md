# Description

Картка слова показує для **основного** (голого) номера Стронга визначення **іншого слова-омоніма**. Пс 29:4 «The voice of the LORD is powerful»: слово כֹּחַ «сила» (H3581, 125 вживань), а в картці — «reptile» / «a small reptile, probably a kind of lizard, which is unclean». Графік «Translated in KJV» під ним при цьому правильний («strength»), тож картка сама собі суперечить.

## Steps to Reproduce

1. Відкрити Пс 29:4 у KJV.
2. Тапнути «is powerful».
3. Вкладка **Word → Meaning**.

## Expected

Лема כֹּחַ, визначення «strength, power, might» (BDB כֹּחַ I).

## Actual

Визначення «reptile» — це כֹּחַ II (ящірка, Лев 11:30), який у Macula має окремий id `H3581a` (1 вживання).

## Notes

### Причина (та сама, що в bug-046, але з протилежного боку)

TBESH і Macula нумерують омоніми **різними схемами суфіксів**:

```
TBESH:   H3581A = «reptile»    H3581B = «strength»    голого H3581 немає
Macula:  H3581  = сила (125)    H3581a = ящірка (1)
```

`import_stepbible_lexicons` пише суфіксований рядок у свій id (`H3581a` ← «reptile» — збіглося випадково правильно), а потім **пропагує суфіксований рядок на голий id, якщо той порожній** (гілка `m_base`, «only fill if the base row's fields are currently NULL/empty»). Першим у файлі йде `a`, тож голий `H3581` отримує «reptile». Правильне визначення (`H3581B`) у базу не потрапляє взагалі — у Macula немає `H3581b`.

bug-046 (закрито варіантом A, 2026-08-19) сховав недостовірні визначення **підзаписів** (444 id у `StrongsDefinitionTrust.swift`). **Голі id ним не покриті** — перевірено: `H1004`, `H5892`, `H3581`, `H6965`, `H5483`, `H8336` у списку відсутні, тож хибне визначення показується як факт. Варіант B з bug-046 (куроване зіставлення Macula ↔ TBESH) відкладено на v1.1 — ця картка показує, що проблема ширша за підзаписи.

### Масштаб (заміряно 2026-10-05; критерії явні)

- **Група ризику:** голі id, що вживаються в Macula, мають у TBESH ≥2 суфіксовані варіанти з різними визначеннями і **не мають** голого рядка — **399 id, 50 742 вживання**. Їхнє визначення взяте з першого варіанта, без перевірки, що це те саме слово.
- **Підозрілі (суворий критерій):** поточне визначення покриває < 10% глос Macula (`word.gloss`) для цього id, а інший варіант TBESH — ≥ 40% → **56 id, 6 468 вживань**. Це нижня межа: часткові збіги (напр. `H5869` «eye» vs «eye: before(the eyes)») сюди не потрапили.

### ⚠️ Урок bug-046, який стосується фікса

Механічне правило «зсунути суфікс» там перевірили на корпусі: виграє 82, програє 41, у 265 із 388 сигналу немає. Тож **ні літера, ні зсув не є відповіддю**. Сигнал «покриття глос Macula» — інший і на цих 56 виглядає однозначним, але його треба валідувати на вибірці вручну, перш ніж довіряти для всіх 399 (особливо імена/топоніми, де глоси Macula короткі).

### Варіанти фікса

- **A′ (швидко, як bug-046):** додати підозрілі голі id у `StrongsDefinitionTrust` → картка показує «No definition available» замість хибного. Нічого не вгадує.
- **B (правильно):** у `import_stepbible_lexicons` для голого id без власного рядка TBESH обирати варіант не за порядком у файлі, а за покриттям глос Macula, з порогами; неоднозначні — у звіт для ручного рішення (кураторський файл на кшталт `data/glosses/`), не мовчки. Заодно — той самий механізм для підзаписів (закриває B з bug-046).
- Еталони в збірці: `H3581` → strength, `H1004` → house, `H5892` → city, `H5483` → horse, `H3581a` → reptile (не зламати), `H2617a` лишається прихованим/«disgrace».
