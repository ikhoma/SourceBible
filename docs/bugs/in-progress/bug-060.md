# Description

У біблійній арамейській визначений артикль — це **суфікс** -א у КІНЦІ слова (емфатичний стан):
סָפְרָא = «писар» (Езд 4:8). Macula ділить таке слово на два токени одного слота:
`סָֽפְרָ` (Ncmsd, H5613) + `א` (Td, art, H1b).

`headToken(of:)` бере **останній не-енклітичний** токен; енклітика = `lexical_class == "x"` або
morph `S…`. Артикль `Td` під жодну умову не підпадає, тож головою слота стає **артикль H1b**,
а не іменник. Наслідки:
- рядок слова в «Оригіналі» показує Strong's/лексикон артикля, а не «писар»;
- слово клікабельне лише якщо переклад тегує H1b (жоден не тегує) → фактично некликабельне.

## Заміряно (2026-10-07, sourcebible.db, лише читання)

**860 слотів**, де `headToken` повертає завершальний `Td`: Дан 644, Езд 211, Єр 10:11 — 5.
Стосується всіх перекладів (це логіка «Оригіналу», не дані перекладу).

## Expected

Голова слота — іменник (H5613), як у івриті, де артикль стоїть ПОПЕРЕДУ і правило «останній
не-енклітичний» працює.

## Пропозиція (реалізовано 2026-10-10, див. Fix)

У `isEnclitic` додати: `morph == "Td"` І токен не перший у слоті (попередній — не проклітика
C/R/Td/Ti/Tr). Той самий критерій уже застосовує конвертер ASV (`scripts/build_asv_module.py`,
`_is_enclitic`) і гейт `scripts/verify_asv_alignment.py` — після фіксу «Оригінал» і теги ASV
вкажуть на одне слово. Swift-зміна → потребує окремого «так».

# Fix (2026-10-10)

`BibleModels.swift`: `isEnclitic(_:after:)` бачить попередній токен слота; `Td` після
не-проклітики (C/R/Td/Ti/Tr) — енклітика. Мовної перевірки не треба: замір на `sourcebible.db`
показав, що правило змінює голову рівно в **860** слотах (Дан 644, Езд 211, Єр 5), усі
арамейські, у івриті — 0. Те саме правило, що `scripts/build_asv_module.py` `_is_enclitic`.
Debug build ✓.
