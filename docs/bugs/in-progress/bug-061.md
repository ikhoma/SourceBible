# Description

Знак виноски (†) і тултіп не з'являються в жодному перекладі, хоча таблиця `footnote`
повна (ASV 10 116, UBIO 1 203, RST 109) і `DatabaseService.loadChapter` заповнює
`BibleVerse.footnotes`.

## Причина

`ReaderViewModel` перебудовує кожен вірш через `BibleVerse(...)` у чотирьох місцях
(сторінки пейджера, `loadChapter()`, слова «Оригіналу», оновлення виділення) і НЕ передає
`footnotes`. Поле має дефолт `[:]`, тож пропуск компілюється мовчки; `VerseTextView` малює
знак лише коли для маркера є текст (`guard footnotes[anchorId] != nil`) → знаків немає ніде.

## Виправлення (2026-10-07)

- Усі чотири перебудови передають `footnotes` і `footnoteLabels`; на полі — ⛔-коментар.
- Разом (рішення Івана): знак — **надрядкова синя літера** a, b, c… у межах глави (після `z` —
  `aa`, `ab`; ASV має до 35 виносок на главу) замість †; зона тапу — на всю висоту рядка, по
  ширині — знак ± 8 pt (`VerseTextView.footnoteHit`, TextKit 1).

## Перевірити на пристрої

Бут 22:8 ASV (літера після «provide», тултіп «Hebrew see for himself.»), Бут 1:2 UBIO,
Бут 3:15 RST; тап поруч зі знаком у межах рядка відкриває тултіп, тап по сусідньому слову — ні.

## Поповер за розміром вмісту (2026-10-07, знайдено на тесті)

`FootnoteTooltip` безумовно загортав текст у `ScrollView` → поповер брав типову висоту, і
однорядкова примітка сиділа в пузирі на три рядки (скріншот Бут 22:8). Тепер
`ViewThatFits(in: .vertical) { текст; ScrollView { текст } }` + явна ширина тексту
(`min(ширина в один рядок, 280 − поля)`), тож пузир обгортає вміст, як системний поповер.
