# Description

At the end of a Matthew Henry commentary, a table of contents plus
"Previous / Next / Free Download / Contact Us" buttons appear as plain text —
boilerplate that leaked into the commentary body.

## Steps to Reproduce

1. Open Есф 3:7 → Henry comment (or Суд 21:16–25).
2. Scroll to the end of the comment.

## Expected

Commentary ends with its content — no table of contents or site nav buttons.

## Actual

TOC + Previous/Next/Free Download/Contact Us rendered as trailing text.

## Screenshots

- Drive mailbox: `img/37.jpg`, `img/37.1.jpg`

## Notes

Tester's own ref: "BUG REPORT 24". iPhone 11 / iOS 26.5.
Smells like a data-cleaning issue in the commentary import (HTML boilerplate not
stripped) rather than UI — check `import_commentaries.py` / the Henry source.

## Investigation (2026-06-26 · subagent, sonnet)

**Real bug (data/import).** In `scripts/import_commentaries.py`, `_henry_extract_sections`
slices the last section to `len(html)` (line 281), and `_strip_henry_html` (215–224)
removes only `<script>/<style>/`tags — not the site footer (chapter TOC + Previous /
Next / Free Download / Contact Us). The footer is converted to text and stored on the
last section.

## Proposed fix

Truncate the HTML before the footer `<TABLE>` (detect nav text) and/or post-strip known
boilerplate phrases. Requires re-running `import_commentaries.py` (rebuilds
`comments`/`comment_verses`; no schema change), then re-bundling the DB — **Mac-only**
per CLAUDE.md. Confidence: high.
