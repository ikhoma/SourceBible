# Description

`loadChapter()` чистить **весь** `pageVersesCache`, а не лише запис глави, що змінилась.
Викликається він після кожного осідання сторінки (відкладено на runloop-такт), тож кеш
сусідів гине рівно тоді, коли сусіди щойно змонтовані й от-от знадобляться.

## Why it matters

Кеш існує саме для сусідніх сторінок (ADR-026: `current ± 1` живе в пейджері), але не
доживає до їх показу — при швидкому гортанні кількох глав поспіль кожне осідання
відправляє наступну сторінку по вірші в базу заново. Ціна — зайві запити й ризик
підморгування вмісту під час жесту, а не помилка даних.

## Investigation notes

- Кеш ключується `book|chapter|translation` — тобто вибіркове прибирання можливе без
  зміни схеми: інвалідувати треба лише ключі, чиї дані справді застаріли (та сама глава,
  зміна перекладу, зміна підсвічувань).
- ⚠️ Обережно: кеш свідомо **не** `@Published` — сторінки читають його під час обчислення
  body. Будь-яке виправлення мусить це зберегти, інакше повернеться повний ре-рендер
  рідера, від якого фаза 2 навмисно тікала.
- Заміру ціни ще немає: скільки саме зайвих `loadChapter` дає гортання, не рахували.
  Перед фіксом варто заміряти — інакше це оптимізація наосліп.

## Possible direction

Прибирати з кешу точково (ключ поточної глави при перезавантаженні; усі ключі перекладу
при його зміні; ключі віршів із зміненим підсвічуванням) замість `removeAll()`.
