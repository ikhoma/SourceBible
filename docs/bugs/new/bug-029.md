# Description

RST stores Psalms in **Synodal / LXX chapter numbering**, which is offset by one
from MT/KJV for Psalms 10–147. Nothing in the app maps chapters between
versification schemes — `verse_map` only maps `trans_verse → macula_verse`
*within an assumed-identical chapter*. For RST Psalms that assumption is false,
so the app aligns verses across two entirely different psalms.

Result: for a reader in RST, everything downstream of `verse_map` in Psalms 10–147
is silently keyed to the wrong psalm.

## Steps to Reproduce

1. Switch translation to RST.
2. Open Пс 89:9 → "Все дни наши прошли во гневе Твоем; мы теряем лета наши, как звук."
   (This is Synodal Ps 89:9 = **Hebrew/KJV Psalm 90:9**.)
3. Open the **Оригінал** tab for that verse.

## Expected

Hebrew text of the psalm the reader is looking at (Heb Ps 90).

## Actual

Hebrew reads `וְשַׂמְתִּי לָעַד זַרְעוֹ וְכִסְאוֹ כִּימֵי שָׁמָיִם` — *"and I will establish his
offspring forever, and his throne like the days of heaven"* — which is **Hebrew Ps 89:30**.
A different psalm entirely.

## Impact — all consumers of verse_map, not just one tab

| Consumer | Symptom in RST Psalms 10–147 |
|---|---|
| Оригінал / word tab | Wrong psalm's Hebrew (shown above) |
| Cross-references (target side) | Correct-looking Russian verse from the wrong psalm |
| Cross-references (source side) | Wrong psalm's cross-ref list |
| Word Usage / concordance | Wrong verse references |

Pre-existing — **not** introduced by the bug-007 fix. bug-007 surfaced it.

## Root cause

`verse_map(translation, book_id, chapter, trans_verse, macula_verse)` has no chapter
dimension. `build_verse_map.py` aligns translation chapter *N* against Macula chapter *N*
by Strong's overlap; for RST Psalms those are different psalms, so the produced rows are
noise rather than a mapping.

## Proposed fix

This is the schema change already prescribed in
`docs/features/verse_versification_system_design.md` (Layer 1–3), never implemented:

1. Replace the Strong's-overlap heuristic with **Paratext `.vrs`** data (`rst.vrs`, `kjv.vrs`)
   as the source of truth.
2. Extend the map to carry **chapter** on both sides + the `to_vsn` column from the design doc,
   so a mapping is `(from_vsn, book, ch, v) → (to_vsn, ch, v)`.
3. Handle the merged/split psalms explicitly — LXX 9 = MT 9+10, LXX 113 = MT 114+115,
   LXX 114+115 = MT 116, LXX 146+147 = MT 147.
4. Land `VersificationService` as the single runtime resolver (design doc Layer 3) and route
   Оригінал, cross-refs and concordance through it.

Needs an ADR + DB rebuild. Sprint-sized, not a bug-fix-sized change.
