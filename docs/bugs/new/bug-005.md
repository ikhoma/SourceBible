# Description

In Ukrainian UI + RST, the word Meaning panel shows English where the tester
expected localized content: (1) the word meaning text is in EN, (2) the
"Лексичне значення" section content is in EN, (3) morphology names (Qal, Niphal,
Piel) are in EN.

## Steps to Reproduce

1. Switch interface to Ukrainian, switch translation to RST.
2. Open Gen 1:21 → tap a word → Meaning.

## Expected

Lexicon meaning and morphology presented in line with the RST/Ukrainian context.

## Actual

Meaning, lexical value, and morphology labels render in English.

- Drive mailbox: `img/30.jpg`, `img/30.1.jpg`

## Notes

Tester's own ref: "BUG REPORT 19". iPhone 11 / iOS 26.5.
TRIAGE FLAG: partially overlaps the known decision that **lexical definitions are
English-only for MVP** (see memory "Dataset language strategy" / ADR-006). The EN
*definition text* may be by-design; but UI labels ("Лексичне значення") and
morphology names (Qal/Niphal/Piel) are localizable — that part is a real gap.
Confirm the split during analysis.

## Investigation (2026-06-26 · subagent, opus)

Split verdict:
- Meaning / definition text in EN — **by design** (Strong's `long_def`/`short_def` are
  English for MVP; ADR-006).
- "Лексичне значення" section label in EN — **real bug**: `MorphKey.sectionLexical`
  resolves via `BundleTranslationProvider`, but the `uk` row is missing in
  `Localizable.xcstrings` (ADR-006's MorphKey-resolution unit test is still unchecked).
- Qal/Niphal/Piel — by-design Latin proper nouns, but **inconsistent**: `decodeHebrew`
  (`WordTabContent.swift` ~770–776) hardcodes literals while `decodeFull` routes through
  `MorphKey.stem*`.

## Proposed fix

Fill the missing `uk` `morph.*` keys in `Localizable.xcstrings` (+ implement the deferred
resolution test). Optionally route `WordTabContent.swift` ~770–776 through `MorphKey` for
consistency. No fix for the English definition text (by-design). Confidence: high on the split.
