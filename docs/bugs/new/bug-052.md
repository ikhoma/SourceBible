# Description

Після (пере)встановлення застосунку рівно перший тап по вірші відкриває Study Mode
sheet із помітною затримкою. Усі наступні тапи в тій самій сесії — миттєво.

## Steps to Reproduce

1. Свіжо (пере)встановити застосунок на пристрій/симулятор.
2. Відкрити читання, тапнути по будь-якому віршу.
3. Спостерігати затримку перед появою sheet'а.
4. Тапнути по іншому вірші — затримки немає.

## Expected

Sheet відкривається без помітної затримки незалежно від того, перший це тап у сесії
чи ні.

## Actual

Перший тап після (пере)встановлення — з затримкою; решта — миттєво.

## Root Cause

`ReaderViewModel.tapVerse()` виконував `loadWordsForSelectedVerse()` синхронно на
main thread, у тому самому виклику, що й `activeSheet = .verse` — SwiftUI не починає
транзакцію презентації sheet'а, поки функція не догорить. `loadWordsForSelectedVerse`
іде в `DatabaseService.loadOriginalWords` → `JOIN word ↔ strongs` за `verse_org`
(`Services/DatabaseService.swift`), а `query()` виконується прямо на потоці виклику
без диспетчеризації (коментар у шапці файлу «heavy work on a background queue» коду
під собою не мав).

Жоден інший запит на шляху запуску не торкається `word`/`strongs`/`cross_reference` —
лише `book`/`translation`/`verse`. Одразу після встановлення OS page cache для
356 MB `sourcebible.db` порожній, тож перший-у-процесі запит до цих таблиць платить
реальний диск I/O; наступні тапи повторно читають вже прогріті сторінки.

## Fix (застосовано)

Комбінація двох підходів:

1. **Прогрів у фоні** (`Services/DatabasePrewarm.swift`, новий файл) — одразу після
   відкриття основного з'єднання `DatabaseService` запускає фонове послідовне
   читання ВСЬОГО файлу `sourcebible.db` (`Task.detached(priority: .utility)`,
   чанками по 4 MB, байти відкидаються). Через ОКРЕМИЙ `FileHandle`, не через
   SQLite-з'єднання: `DatabaseService.db` документовано односпотоковий
   (`SQLITE_OPEN_NOMUTEX`), тож чіпати його з фонового потоку не можна — але сирий
   байтовий read того самого файлу так само наповнює OS-рівневий page cache,
   яким користуються всі з'єднання, включно з основним. Читається весь файл, а не
   тільки «потрібні» таблиці/рядки: цілі перехресних посилань (`cross_reference`
   → `verse_org` → текст вірша) розкидані по всій Біблії практично випадково,
   тож прогріти саме те, що знадобиться конкретному тапу, наперед неможливо.

2. **Прибрано з критичного шляху презентації sheet'а**:
   - `tapVerse()` — `loadWordsForSelectedVerse()` (живить лише вкладку
     «Оригінал», НЕ ту, на якій sheet відкривається) винесено в
     `Task { await Task.yield(); ... }` — на один тік пізніше, після того як
     стан `activeSheet = .verse` встиг дійти до SwiftUI.
   - `VerseTabView.loadData()` — `vm.loadCrossReferences()` (вкладка «Перехресні
     посилання» — саме та, яку sheet показує за замовчуванням, `versePill = .crossRefs`
     у `VerseBottomSheetView`) лишився синхронним/пріоритетним: користувач бачить
     4-5 перехресних посилань одразу. `vm.loadParallelVerses()` (вкладка
     «Переклади», не видима без перемикання) так само відкладено на один тік.

Build перевірено: `xcodebuild` на iPhone 17 (iOS 26.5) і iPhone 16 Pro (iOS 18.0) —
0 помилок, 0 попереджень.

Instruments Time Profiler на перший тап, це підтвердить чи спростує гіпотезу.
