# Description

Невірний відмінок у підрахунку розділів на обкладинці: «Малі пророки · 3 **розділів**»
замість «3 **розділи**» (підтверджено скріншотом на Авакумі).

## Expected

2 розділи, 3 розділи, 4 розділи — і 1 розділ, 5 розділів, 11 розділів.

## Investigation (2026-08-17)

Два незалежних дефекти в одному рядку інтерфейсу.

**1. Англійське правило множини в Swift.** `BookCoverData.subtitle` мав тернар:

```swift
let unit = chapterCount == 1 ? NSLocalizedString("cover.chapter") : NSLocalizedString("cover.chapters")
```

Дві форми — це правило англійської. Українська має три (one/few/many), тож усе, що
не 1, отримувало «розділів».

**2. Заміряно на симуляторі: локаль ≠ бандл.** Після переходу на plural-варіації в
`Localizable.xcstrings` обкладинка показала «3 **розділу**» — тобто взяла українську
таблицю, але **англійське** правило (3 → `other`). Причина: swizzle `LocalizedBundle`
(ADR-006) підміняє БАНДЛ, з якого беруться рядки, але не `Locale.current`. А
`String.localizedStringWithFormat` пінить рулі саме до `Locale.current`, тобто до
СИСТЕМНОЇ мови (в симуляторі — en). Правильно: `String(format:locale:)` з `\.locale`
середовища, яку `SourceBibleApp.swift:193` уже виставляє з `appLanguage`.

Це і є найцінніша частина цього багу: перший фікс виглядав правильним і компілювався,
а помилку показав лише **запуск**. Ця ж пастка лежала ще у двох місцях (нижче).

## Scope (той самий клас, не лише обкладинки)

Аудит усіх ключів із числом у `Localizable.xcstrings`:

| поверхня | було | стан |
|---|---|---|
| обкладинка книги | «3 розділів» | виправлено |
| «Знайдено N результатів» (Пошук) | «2 результатів» | виправлено (plural-варіації; `Text` бере локаль із середовища) |
| «N випадків у Біблії» (Слово → Вживання) | «2 випадків» | виправлено (+ `locale:` явно) |
| «N у цій книзі» (Вживання, по книгах) | без узгодження за формою | не було багу, локаль додано для однорідності |
| «%d гл.» (пікер, навігація) | скорочення | не потребує plural |

Мертві ключі, знайдені дорогою і прибрані: `search.results_count`,
`search.results_count_max %lld`, `word.usage.count` (усі `stale`, жодного посилання в
Swift) + мертва константа `MorphKey.usageCount`.

## Fix (2026-08-17)

- `cover.chapters_count`, `search.results_count %lld`, `word.usage.total_count` —
  plural-варіації з ПОВНИМ набором категорій uk (one/few/many/other).
- `BookCoverData.info(for:chapterCount:locale:)` — локаль стала явним параметром,
  `BookCoverView` передає `\.locale`; `ConcordanceView` і `BookUsageRow` отримали
  `@Environment(\.locale)`.
- Формат — `String(format:locale:)`. `String.localizedStringWithFormat` і
  `String(format:)` без локалі з цього дня заборонені на plural-ключах.

**Перевірено запуском** (iPhone 17 / iOS 26.5, `-appLanguage uk`):
Авакум → «Малі пророки · 3 розділи», Обадія → «Малі пророки · 1 розділ».

## Prevention

`scripts/lint_localization.py` — ненульовий код виходу, чотири перевірки:

1. ключ із `%lld`/`%d` біля іменника в uk БЕЗ plural-варіацій (з винятками для
   скорочень типу «гл.»);
2. plural-ключ без повного набору категорій uk;
3. plural-ключ, форматований `localizedStringWithFormat` або `String(format:)` **без**
   `locale:` — тобто той самий системно-локальний капкан, що дав «3 розділу»;
4. тернар «однина/множина» навколо `NSLocalizedString`.

Негативні прогони зроблено: знято plural → падає; вилучено категорію `few` → падає;
повернено `localizedStringWithFormat` → падає з поясненням.
