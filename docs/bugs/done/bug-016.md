# Description

Opening a John Calvin commentary sometimes shows an empty state ("No commentary
available for this verse") instead of text. It looks random across books.
Expected: don't offer a commentary that has no text for the verse.

## Steps to Reproduce

1. Open Josh 17:2.
2. Verse sheet → Commentaries → tap John Calvin.
3. Empty state appears even though Calvin is listed.

## Expected

A theologian is only offered when tapping them shows real commentary text.

## Actual

Calvin (and other sources) are listed for any verse in a book they cover
*somewhere*, so verses inside a coverage gap open an empty page.

## Screenshots

- `img/6.1.jpg` — Commentaries list at Josh 17:2 offers John Calvin + Matthew Henry.
- `img/6.jpg`   — tapping Calvin → "No commentary available for this verse."

## Investigation (2026-07-16)

**Real bug — structural, not data-random.** The picker offered a theologian using
`DatabaseService.commentarySourcesAvailable(bookId:)` — **book** granularity (the source
has *any* section in the book). But `CommentaryDetailView` loads **per verse** via the
`comment_verses` lookup index. The Calvin/Henry MyBible/SWORD modules are patchy
(ADR-027: Calvin's Isaiah stops at ch. 48; gaps in Gen 10–30, John 6). At Josh 17:2,
Calvin is offered because he has sections elsewhere in Joshua, but no `comment_verses`
row covers 17:2 → `loadCommentary` returns nil → empty state. Whether a given verse is
empty depends purely on whether it falls in that source's coverage gap — hence
"random across books."

Files: `SourceBible/Views/BottomSheet/VerseTabContent.swift` (`CommentariesView`),
`SourceBible/Services/DatabaseService.swift`.

## Fix

**Root cause:** commentary availability was computed per book, but content is per verse;
sources were offered on verses they don't actually cover.

**Changed:**
- `DatabaseService.swift` — added `commentarySourcesAvailable(bookId:chapter:verse:)`
  that JOINs `comment_verses` and requires non-blank text
  (`TRIM(c.text, space|tab|CR|LF) <> ''`), so only sources with a real section for
  *this* verse are returned.
- `VerseTabContent.swift` — `CommentariesView` now filters the picker on the per-verse
  set (`.task(id: verseId)`, parsing chapter/verse from the verseId, with a book-level
  fallback for an unparseable id). Its empty state now uses the existing localized key
  `verse.commentary.unavailable` ("No commentary available for this verse.").
- `DatabaseService.loadCommentary(...)` — applied the *same* non-blank filter plus
  `ORDER BY c.id LIMIT 1`, so the availability check and the load agree (a verse mapped
  to multiple rows where one is blank can no longer open empty).

**Verification:** `idx_cv(book_id, chapter, verse)` index confirmed present
(`scripts/import_commentaries.py`), so the per-verse query is index-backed. Independent
review = SHIP-WITH-CAVEAT; the flagged availability/load mismatch was then closed by the
`loadCommentary` change. Not compiled/run here (no Swift toolchain on the bridge) —
on-device check after Clean Build: at Josh 17:2 Calvin is no longer listed (Henry still
is), and a covered verse (e.g. a Calvin-covered verse) still opens correctly.
