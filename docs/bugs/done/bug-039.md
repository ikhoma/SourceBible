# Description

Скрол у вкладці «Значення» зберігається при переході на ІНШЕ слово: стаття словника
відкривається не з початку, а там, де користувач скролив попереднє слово.

## Steps to Reproduce

1. Study Mode → тап по слову → вкладка «Слово» → «Значення».
2. Проскролити статтю вниз.
3. Перейти на сусіднє слово (шеврони або лонгтап по іншому слові у вірші).

## Expected

Нове слово — стаття з початку.

## Actual

Той самий offset, що лишився від попереднього слова.

## Investigation (2026-08-17)

`VerseBottomSheetView.swift:63` — механізм скидання скролу в проєкті вже був
правильний (`.id()` на `ScrollView`, комент прямо це описує), але **ключ не містив
суб'єкта**:

```swift
.id(vm.bottomSheetMode == .verse ? "verse-\(versePill)" : "word-\(wordSubTab)")
```

У ключі лише пілюля / підвкладка. Тому зміна пілюлі скрол скидала, а зміна
`selectedWord` / `selectedSegment` (bug-039) чи `selectedVerse` (bug-040) — ні:
`ScrollView` лишався тим самим, вміст мінявся під старим offset-ом.

**Третій випадок, якого ніхто не репортив:** `VerseTabContent` перезавантажує дані ще й
на зміну перекладу (`onChange(of: vm.currentTranslation.id)`, рядок 44) — тобто зміна
перекладу з відкритим sheet-ом давала те саме.

## Fix (2026-08-17)

`scrollSubjectId` — ключ тепер несе **суб'єкт**, а не лише вкладку: пілюля/підвкладка
+ `verse.id` + `selectedWord.id`/`selectedSegment.id` + `currentTranslation.id`.
Один ключ закриває всі три випадки (039, 040 і переклад).

Поруч поставлено ⛔-комент: додаєш нове джерело даних у цю область — додай його
ідентичність у ключ, інакше вміст поїде під старим скролом і баг повернеться.

## Prevention

- ⚠️ Swift-тестів у проєкті немає (один native target), тож перевірено збіркою
  (Debug, iPhone 17 / iOS 26.5, 0 errors) + читанням ланцюга станів. Взаємодію
  (скрол → шеврон) лишається перевірити руками — вона не автоматизується наявними
  інструментами.
- Ризик, який варто мати на увазі при ревʼю: `ScrollView` тепер пересоздається на
  кожній зміні вірша, а висота sheet-а керується дуальним механізмом (ADR-021,
  `StudySheetDetent` + `StudySheetDetentApplier`). Перевірити на живому пристрої, що
  перехід шевронами не смикає висоту.
