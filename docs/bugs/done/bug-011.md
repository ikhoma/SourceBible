# Description

When opening a word from search results a second time, the large clear ("X")
button next to the search field is missing (only the inner one remains). On the
first open it is present.

## Steps to Reproduce

1. Open search, search three different words.
2. Open each word one by one.
3. On the second word-open from search, the big clear button is gone.

## Expected

The clear button is present after every word open.

## Actual

Present on first open, missing on subsequent opens (only inner clear remains).

## Screenshots

- Drive mailbox: `img/38.jpg`, `img/38.1.jpg`

## Notes

Tester's own ref: "BUG REPORT 25". iPhone 11 / iOS 26.5.
Likely a view-state / search-bar lifecycle issue on repeated navigation.

## Investigation (2026-06-26 · subagent, sonnet)

**Real bug.** `SearchView.swift` — opening a result switches to the `.bible` tab; the
system flips `.searchable`'s `isPresented` binding (`isSearchActive`, line 18) to false
on the hidden tab. On return, `committedQuery` is still set so results render, but the
system search bar (which draws the large clear "X") isn't active → outer X missing.
First open still has `isSearchActive = true`, so it's present then.

## Proposed fix

On `onAppear` (or `onChange(of: isSearchActive)`) re-assert `isSearchActive = true` when
`committedQuery` is non-empty. Confidence: high.

## Fix (2026-07-16)

**Root cause:** Opening a result sets `router.pendingVerseId`; `ContentView` flips
`selectedTab` to `.bible`, which deselects the `Tab(role: .search)` hosting `SearchView`.
The system then collapses that tab's `.searchable` presentation (`isSearchActive -> false`).
On return the results page still renders (it is driven by `committedQuery`, not
`isSearchActive`), but the system search bar that draws the large clear (X) button is
inactive -> the outer X is missing on the 2nd+ open. The first open still has
`isSearchActive == true`, which is why it is present only the first time.
Confirmed visually: `img/38.jpg` (X present) vs `img/38.1.jpg` (X gone, inner clear only).

**Changed:**
- `SourceBible/Views/Search/SearchView.swift` - added `reassertSearchPresentationIfNeeded()`
  which sets `isSearchActive = true` when `isShowingResults && !isSearchActive`, then drops
  the keyboard on the next tick (`Task { @MainActor in dismissKeyboard() }`) to match the
  keyboard-free committed state. Added an `isSelectedTab: Bool = true` input; the restore is
  driven by `.onChange(of: isSelectedTab)` (reliable for a `role: .search` tab) with
  `.onAppear` as an idempotent backup. The `isShowingResults` guard leaves the Cancel/X flow
  and the mid-typing state untouched.
- `SourceBible/ContentView.swift` - both `SearchView(...)` call sites (iOS 18 + fallback)
  now pass `isSelectedTab: selectedTab == .search`.

**Verification:** exact-anchor edits; braces/parens balanced; independent review = SHIP-WITH-CAVEAT.
Not compiled/run in this environment (no Swift toolchain on the bridge). On-device check after
Clean Build: (a) the large X returns on every re-open of a result, and (b) no keyboard flash on
return to the results page.
