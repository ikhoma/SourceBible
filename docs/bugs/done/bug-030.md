# Description

У Study Mode тулбарні чеврони `‹ ›` мають перемикати вірші (spec-study-mode-redesign R5).
На **iOS 18** тап по чеврону натомість **закриває sheet**. Глава при цьому НЕ змінюється —
тобто це не «чеврон впав у гілку перегортання глав», а тап взагалі не доходить до кнопки.

**Проявилось уперше після зниження deployment target 26.4 → 18.0 (Phase B, 2026-07-31).**
Це не регресія коду: під target=26.4 застосунок фізично не міг запуститись на iOS 18,
тож поведінка sheet'а на цьому рантаймі ніколи не виконувалась. Flip зробив її досяжною.

## Steps to Reproduce

1. Зібрати гілку `ios18-target-flip`, запустити на симуляторі **iOS 18.0**.
2. Відкрити будь-яку главу (відтворено на Пс 34, KJV).
3. Тапнути вірш у середині глави → Study Mode, sheet відкривається, тулбар морфиться в «Close ‹ ›».
4. Тапнути правий чеврон `›`.

## Expected

Перехід на наступний вірш (Пс 34:2 → 34:3), sheet лишається відкритим, вміст перезавантажується.

## Actual

Sheet закривається. Рідер лишається на тій самій главі, вірш не змінюється.

## ROOT CAUSE (знайдено 2026-08-01, рісьорч + читання коду)

**`largestUndimmedDetentIdentifier` вказує на detent, якого більше немає в `sheet.detents`.**

Ланцюг:

1. SwiftUI-модифікатор `.presentationBackgroundInteraction(.enabled)` (`ReaderView.swift:167`)
   під капотом виставляє `UISheetPresentationController.largestUndimmedDetentIdentifier`
   на ідентифікатор найбільшого зі СВОЇХ detent'ів — тобто `.custom(StudySheetDetent.self)`.
2. Далі `StudySheetDetentApplier` (`StudySheetDetent.swift:78-86`) свідомо обходить
   SwiftUI-плюмбінг і **ЗАМІНЮЄ весь набір**:
   `sheet.detents = [Detent.custom(identifier: .init("studySheet")) { … }]`.
3. Тепер `largestUndimmedDetentIdentifier` посилається на ідентифікатор, якого в
   `sheet.detents` **вже не існує**.
4. Документована поведінка UIKit: щоб undimming діяв, найбільший undimmed detent
   **мусить бути присутнім у колекції detent'ів**. Ідентифікатор-сирота → undimming
   тихо не застосовується.
5. Без undimming sheet поводиться як звичайний модальний: фон неінтерактивний,
   **тап поза sheet'ом = dismiss**. Тулбар — саме «поза sheet'ом».

Applier **ніде не виставляє** `largestUndimmedDetentIdentifier` — перевірено, весь файл прочитано.

### Чому це узгоджується з усіма фактами

- **Чому a11y бачить кнопки активними.** Дерево доступності обходить усю ієрархію
  незалежно від dimming; hit-test — ні. Звідси розбіжність шарів.
- **Чому зняття `presentationSizing` не допомогло.** Він до цього ланцюга не причетний.
- **Чому зняття `EdgeSwipeNavigator` не допомогло.** Так само.
- **Чому code review #7 «спалився» на `.enabled(upThrough:)`.** Будь-який названий там
  detent так само не збігався з рантайм-встановленим `"studySheet"` → dimming повертався.
  Висновок «restricting brings back dimming» був правильним спостереженням із хибним
  поясненням: проблема не в `upThrough`, а в неспівпадінні ідентифікаторів.
- **Чому на iOS 26 працює.** Пізніший UIKit, вочевидь, толерує сироту й відкочується
  до «найбільший наявний», або SwiftUI переприкладає властивість після зміни detent'ів.
  Для фіксу це не має значення — фікс коректний на обох.

## Рекомендований фікс (2 рядки, БЕЗ переносу UI)

У `StudySheetDetentApplier.apply(animated:)`, там де вже встановлюються detent'и,
додатково виставити undimmed-ідентифікатор на ТОЙ САМИЙ detent:

```
let id = UISheetPresentationController.Detent.Identifier("studySheet")
let detent = UISheetPresentationController.Detent.custom(identifier: id) { … }
sheet.detents = [detent]
sheet.largestUndimmedDetentIdentifier = id   // ← бракує саме цього
```

Обидва присвоєння мають бути в одній `animateChanges`-транзакції, щоб між зміною набору
й undimmed-ідентифікатора не було кадру-сироти.

⚠️ Не чіпати `.presentationBackgroundInteraction(.enabled)` у `ReaderView` — він лишається
як декларація наміру для SwiftUI-шляху; заборона з code review #7 діє.

### Чому цей напрям кращий за «чеврони в sheet»

Перенос навігації в sheet тягне за собою екшн-меню, `…`, вкладки Verse/Word — тобто
переробку композиції R5 і розходження UI між 18 і 26. Тут — правка в тому самому місці,
яке вже й так лізе в UIKit, нуль змін у структурі екрана, нуль розходжень між версіями.

### Запасний план, якщо не спрацює

1. Виставляти `largestUndimmedDetentIdentifier` в `didMoveToWindow` ПІСЛЯ першого
   `apply(animated:false)` окремим проходом (проблема порядку застосування).
2. Відмовитись від UIKit-підміни detent'ів: тримати єдиний `.custom(StudySheetDetent.self)`
   і покластись на `invalidateDetents()`. Прибирає першопричину, але воскрешає баг ресайзу,
   заради якого applier і писався.
3. Архітектурна: замінити sheet на child-view controller / overlay з власним драгом —
   повний контроль над hit-test'ом. Так роблять, коли sheet-семантика заважає; дорого.
4. Платформено-ідіоматична (те, що робить сам Apple у Maps/Find My): не тримати
   nav bar під sheet'ом узагалі — контроли живуть у sheet, а на фоні лише плаваючі кнопки.
   Найдорожча, тягне R5.

detent'а винесено в `Self.detentID`, і разом із `sheet.detents = [detent]` тепер виставляється

Коментар у `ReaderView.swift:148-152` стверджував, що `presentationBackgroundInteraction(.enabled)`
