# Description 
The last word H3887a for which we created a mapping from extended NASB Strongs doen't highighted in the Verse text

## Screenshots
- ../bugs/img/bug-003-1.png

## Fix

**Root cause:** `syncSegment`, `selectedWordDisplayText`, and `translationOrderedClickableWords` all matched segment Strong's IDs using `baseStrongsNumber` only, which strips letters/suffixes but doesn't resolve NASB extended numbers (e.g. "9238" → "3887"). So H3887a (Macula base "3887") couldn't find its NASB segment "S9238" and `selectedSegment` stayed nil — no highlight.
**Changed:** `ReaderViewModel.swift` — added `resolvedMaculaBase(_:)` helper that applies `nasbExtendedOverride` after stripping. Replaced `baseStrongsNumber` with `resolvedMaculaBase` in all three segment-matching sites.
**Status:** done

## Verification

Verified on device 2026-07-14 (Ivan). Repro case Ps 1:1 NASB — "scoffers" (לֵצִים, H3887a)
now taps and highlights. Confirmed working across **all** translations: the NASB extended
path resolves, and KJV/RST are unaffected (the override is a no-op there).

**Note — the code has moved on from the description above.** All consumers (highlight,
`clickableWordIDs`, `syncSegment`, `translationOrderedClickableWords`) now derive from the
single canonical `verseWordSegmentPairs`, which applies `resolvedMaculaBase` on the segment
side (`ReaderViewModel.swift:369`) and `baseStrongsNumber` on the Macula-word side (:361).
One matching path, not three.
