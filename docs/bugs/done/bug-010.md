# Description

At the end of a Matthew Henry commentary, a table of contents plus
"Previous / Next / Free Download / Contact Us" buttons appear as plain text —
boilerplate that leaked into the commentary body.

## Steps to Reproduce

1. Open Есф 3:7 → Henry comment (or Суд 21:16–25).
2. Scroll to the end of the comment.

## Expected

Commentary ends with its content — no table of contents or site nav buttons.

## Actual

TOC + Previous/Next/Free Download/Contact Us rendered as trailing text.

## Screenshots

- Drive mailbox: `img/37.jpg`, `img/37.1.jpg`

## Notes

Tester's own ref: "BUG REPORT 24". iPhone 11 / iOS 26.5.
Smells like a data-cleaning issue in the commentary import (HTML boilerplate not
stripped) rather than UI — check `import_commentaries.py` / the Henry source.

## Investigation (2026-06-26 · subagent, sonnet)

**Real bug (data/import).** In `scripts/import_commentaries.py`, `_henry_extract_sections`
slices the last section to `len(html)` (line 281), and `_strip_henry_html` (215–224)
removes only `<script>/<style>/`tags — not the site footer (chapter TOC + Previous /
Next / Free Download / Contact Us). The footer is converted to text and stored on the
last section.

## Proposed fix

Truncate the HTML before the footer `<TABLE>` (detect nav text) and/or post-strip known
boilerplate phrases. Requires re-running `import_commentaries.py` (rebuilds
`comments`/`comment_verses`; no schema change), then re-bundling the DB — **Mac-only**
per CLAUDE.md. Confidence: high.

## Fix (2026-07-16)

**Root cause:** Every Matthew Henry chapter HTML ends with a `<!-- (End Body) -->`
comment followed by the site footer (Table of Contents / Previous / Next /
"Matthew Henry — Commentary on the Whole Bible (1708)" / Back to BiblesNet /
Free Download / Contact Us). `_henry_extract_sections` slices the final section to
`len(html)`, and `_strip_henry_html` only strips `<script>/<style>`, so that footer
was converted to text and stored on each chapter's last section.

**Changed:** `scripts/import_commentaries.py` — `_henry_extract_sections` now truncates
at the body-end marker before extracting sections:

```python
html = re.split(r"<!\s*--\s*\(End Body\)\s*-->", html, maxsplit=1)[0]
```

The `\s*` tolerates the one malformed marker in the source (`<! -- (End Body) -->`,
Habakkuk 1). If the marker were ever absent, the split returns the full HTML — same as
before, no regression.

**Verified (read-only, no DB write):** ran the *patched* `_henry_extract_sections` over
all 1195 Henry chapter files / 2653 sections → **0** footer leaks (previously every
chapter's last section leaked), **0** emptied sections. Both reported passages now end
on their real last sentence:
- Суд 21:16–25 → "…every man would be his own master, as if there was no king. Blessed
  be God for magistracy."
- Есф 3:7–15 → "…to indulge ourselves in mirth and pleasure when the church is in
  distress and the public are perplexed."

**⚠️ Requires a Mac-side rebuild to reach the app.** The bundled DB still holds the old
text; the DB build is Mac-only per CLAUDE.md and was NOT run from the Linux bridge (APFS
sparse-file corruption risk). On the Mac:

```
python3 scripts/import_commentaries.py sourcebible.db
cp sourcebible.db SourceBible/Resources/sourcebible.db
```

then Clean Build Folder (⇧⌘K) → Run.
