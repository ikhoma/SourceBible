# Description

With RST active, cross references render in both English and RST. Expected: only
RST when RST is the active translation.

## Steps to Reproduce

1. Switch translation to RST.
2. Open 2Цар 22:51 → Cross references.

## Expected

Cross-reference verses shown only in RST.

## Actual

Both EN and RST shown.

## Screenshots

- Drive mailbox: `img/34.jpg`

## Notes

Tester's own ref: "BUG REPORT 21". iPhone 11 / iOS 26.5.

## Investigation (2026-06-26 · subagent, opus)

**Real bug.** `DatabaseService.loadCrossReferences` (~619–658) COALESCEs the target
text to a hardcoded `defaultFallbackTranslation = "KJV"` (line 40). When the RST row
is absent it substitutes English; the query sets `is_fallback` → `CrossReference.isFallback`,
but `CrossRefsView` (`VerseTabContent.swift` ~162–189) renders `targetText` and never
reads the flag → mixed RST/English list.

## Proposed fix

In `CrossRefsView`, when `ref.isFallback` is true, suppress the English text and show
the existing `"verse.text_unavailable"` placeholder (RST-only). Confidence: high.

## Fix (2026-07-13)

The 06-26 investigation was right about the mechanism but wrong about the cause.
The RST verses aren't missing from the DB — they're stored under **different numbers**.

**Root cause.** `cross_reference` is numbered in KJV/OpenBible versification on *both*
endpoints. `loadCrossReferences` joined `verse` on `v.verse = xr.to_verse` for the active
translation, i.e. it assumed RST numbers verses like KJV. It doesn't: RST is LXX-based for
the OT, so Psalm superscriptions count as verse 1 and the numbering shifts across the ~459
chapters tracked in `verse_map`. No RST row at that number → `COALESCE` substituted KJV →
English text next to Russian.

2 Sam 22:51 is the worst case in the Bible for this: **12 of its 16 cross-refs are Psalms**.
Non-Psalm refs (2 Sam 7:12, Jer 30:9, Luke 1:31) rendered in RST correctly — hence the
mixed list the tester saw.

Suppressing the text (the original proposal) would have hidden verses that exist.

**Changed:**
- `DatabaseService.swift`
  - `+ crossRefVersification` constant (the scheme `cross_reference` is numbered in).
  - `+ findTranslationVerse()` — reverse of `findMaculaVerse` (MT → translation).
  - `+ convertVerse(from:to:)` — routes any translation→translation hop through MT.
  - `loadCrossReferences` rewritten: the **source** verse is converted to KJV numbering
    before the query; the **target** verse is routed `xr.to_verse (KJV) → MT → translation`
    via two `verse_map` joins, so text, printed reference and tap target all speak the
    reader's versification. Same two-hop pattern Word Usage already used.
- `VerseTabContent.swift` — `CrossRefsView` now shows the `verse.text_unavailable`
  placeholder when `isFallback`, so the fallback translation is never printed alongside
  the active one. Post-fix, `isFallback` means the verse is genuinely absent.

**Verified** on iPhone 17 Pro sim / iOS 26.5, RST, 2 Цар 22:51: no English in the list;
`Пс 3:4` now resolves to the correct verse, correct label, correct tap target.

**Known remaining gap → bug-029.** RST stores Psalms in Synodal/LXX *chapter* numbering
(Ps 10–147 offset by one) and `verse_map` has no chapter dimension. Cross-refs into that
range still land on the wrong psalm. That defect is pre-existing and app-wide (it also
makes the Оригінал tab show the wrong Hebrew for RST Psalms) — it needs the chapter-aware
versification map from `docs/features/verse_versification_system_design.md`. Tracked
separately; this fix is a strict improvement over the previous behaviour.
