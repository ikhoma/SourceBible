# Description

With the red-letter toggle on, ASV shows no red text. Expected: red letters in any translation.

## Steps to Reproduce

1. Turn on the red-letter toggle.
2. Open Mark 1 in ASV.

## Root cause (2026-07-14) — not a code bug

The **ASV source module has no red-letter markup at all.** Counted `<J>` tags directly in
the MyBible modules under `data/`:

| Module | Verses with `<J>` |
|---|---|
| KJV+ | 2 051 |
| NASB+ | 2 047 |
| RST+ | 2 060 |
| **ASV+** | **0** / 31 085 |

The app path is correct end to end — `VerseParser` maps `<J>` → `SegmentStyle.jesusWords`,
and `VerseTextView.resolveColor` renders `.systemRed` when the red-letter preference is on.
There is simply nothing in the ASV text to color.

Confirmed on Mark 1:15 and 1:17: red in KJV/NASB/RST, plain in ASV, and the raw ASV rows
contain only `<S>` Strong's tags, no `<J>`.

## Blocked on — decision needed

### Option A — synthesize the markup from KJV

For each `<J>` span in the KJV verse, locate its first and last Strong's number in the
corresponding ASV verse and wrap that contiguous ASV run in `<J>`.

Feasibility measured against the real modules:

- 2 038 of 2 042 KJV red-letter verses have Strong's overlap with ASV → alignment is viable.
- 1 404 verses are **fully** Jesus' words → whole-verse wrap, trivially safe.
- 647 verses are **partial** (narrative + speech in one verse) → need span alignment; this
  is where mis-coloring could creep in, so the script should emit a low-confidence report
  to eyeball rather than trusting all 2 051 blind.

Deliverable: `scripts/add_asv_red_letters.py`, patching the `verse` table in place (no full
10-minute rebuild). Must be run on the Mac — never read `sourcebible.db` from a Linux sandbox.

### Option B — gate the toggle per translation

Detect that a translation carries no `<J>` and disable or hide the red-letter toggle for it,
so the toggle never silently does nothing. Small, ships immediately, honest — but ASV readers
never get red letters.

Worth doing as a safety net regardless: any future translation without markup then degrades
gracefully instead of reproducing this ticket.

### Option C — source a red-letter ASV module

Replace `data/ASV+.zip` with a module that ships `<J>`. Cleanest data-wise; depends on such a
module existing under a compatible licence.

## Notes

Severity stays low (P3): the toggle works correctly in KJV, NASB and RST — three of four
translations. The ASV gap is a data hole, not a regression.
